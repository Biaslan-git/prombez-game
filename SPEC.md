## 1. Что делаем

Веб-тренажёр для подготовки к аттестации по промышленной безопасности в Ростехнадзоре (тестирование на ЕПТ).

**Главный принцип:** от захода на сайт до первого вопроса проходит не больше одного клика. Никакой регистрации, онбординга и попапов до первого ответа.

**Аудитория:** взрослые работающие люди (инженеры, мастера, руководители), готовятся с телефона урывками в течение 2–4 недель.

**Монетизация в MVP:** Рекламная сеть Яндекса (РСЯ). В будущем: Pro-подписка и B2B-кабинет (вне MVP, но архитектура не должна им мешать).

**Ценность для пользователя:**
1. Сразу решать вопросы своей области.
2. Видеть процент готовности к экзамену.
3. Понимать, почему ответ правильный (объяснение со ссылкой на норму).
4. Тренировать ошибки с умным повторением.
5. Пройти пробный экзамен в формате реального.

## 2. Стек

- **Next.js** (App Router) + **TypeScript** (strict) + **Tailwind CSS**
- **PostgreSQL** + **Drizzle ORM** (миграции через drizzle-kit)
- Валидация: **zod**
- Тесты: **Vitest** (логика), **Playwright** (1–2 e2e-сценария)
- Деплой: **Docker** (multi-stage, `output: "standalone"`) → **Dokploy** + Traefik
- Аналитика: **Яндекс Метрика**
- Импорт вопросов: Node/TS-скрипт в `scripts/` (парсер исходников может быть отдельным, на Python; на вход импорта подаётся JSON)

Отдельного бэкенда в MVP нет: всё внутри Next.js (Server Components, Route Handlers, Server Actions).

Поддержать несколько правильных ответов на один вопрос (тогда в UI чекбоксы и кнопка «Ответить»).

### Прогресс в MVP
**Хранится на клиенте** (localStorage, ключ `pg:v1:progress:{areaSlug}`), без аккаунтов. Схема:

```ts
type QuestionProgress = {
  box: 0 | 1 | 2 | 3 | 4 | 5;  // ячейка Лейтнера
  attempts: number;
  wrong: number;
  lastAnsweredAt: number;      // ms
  nextReviewAt: number;        // ms
  lastResults: boolean[];      // последние 3 результата
};
type AreaProgress = {
  version: 1;
  questions: Record<number /* questionId */, QuestionProgress>;
  exams: { at: number; correct: number; total: number; passed: boolean }[];
  streak: { lastDay: string /* YYYY-MM-DD */; days: number };
};
```

Весь доступ к хранилищу идёт через `lib/progress/storage.ts` и обёрнут в try/catch. Интерфейс сделать таким, чтобы на этапе аккаунтов можно было подменить реализацию на серверную, не трогая UI.

## 5. Логика

### 5.1 Интервальное повторение (Лейтнер)
- Верный ответ: `box = min(box + 1, 5)`; неверный: `box = 1`.
- Интервалы до следующего показа по ячейкам: 1 → 0 дней (в этой же сессии), 2 → 1 день, 3 → 3 дня, 4 → 7 дней, 5 → 14 дней.
- **Выбор следующего вопроса в тренировке:**
  1. Просроченные (`nextReviewAt <= now`), сначала с меньшим box.
  2. Новые (ни разу не отвеченные), по порядку номеров.
  3. Если всё изучено и ничего не просрочено, показываем вопросы с самым ранним `nextReviewAt` и сообщение «На сегодня всё повторено 💪».
- Вопрос, на который только что ответили неверно, повторить через 3–5 вопросов в той же сессии.

### 5.2 Готовность к экзамену
- Вопрос считается **освоенным**, если `box >= 3` и последний ответ верный.
- `readiness = round(освоенные / всего_активных * 100)`.
- Показывается крупно на странице области и в шапке тренировки.
- Подписи: 0–39% «Только начали», 40–69% «Уже неплохо», 70–89% «Почти готовы», 90%+ «Готовы к экзамену».

### 5.3 Экзамен
- Случайные `exam_questions_count` активных вопросов области, порядок ответов перемешан.
- Таймер `exam_time_limit_min`. По истечении времени экзамен завершается автоматически.
- Во время экзамена **нет** подсветки правильных ответов и **нет рекламы**.
- Можно переходить между вопросами и менять ответ до завершения (навигация по номерам).
- Результат: «Сдал / Не сдал», X из Y, список ошибок с правильными ответами и объяснениями. Ошибки экзамена обновляют прогресс так же, как в тренировке.

### 5.4 Работа над ошибками
Вопросы, где `lastResults` содержит хотя бы один `false` и при этом `box < 3`. Если список пуст, показываем «Ошибок нет 🎉» и кнопку экзамена.

### 5.5 Геймификация («game» в домене)
Лёгкая, без перегруза:
- **Серия дней** 🔥: день засчитывается, если ответил хотя бы на 10 вопросов.
- **Шкала готовности** (см. 5.2) как главный индикатор.
- После каждых 10 ответов короткая плашка с итогом мини-сессии: «8 из 10 верно, готовность +3%».

Очков, уровней и рейтингов в MVP нет.

## 6. Страницы и UX

### Общие требования
- **Mobile first** (проверять на ширине 360px), кнопки ответов на всю ширину, высота от 48px.
- Тёмная и светлая тема (системная плюс переключатель).
- Десктоп: клавиши `1–9` выбирают ответ, `Enter` — ответить или перейти дальше.
- Мобильный: после ответа кнопка «Дальше» закреплена внизу экрана.
- Шрифт крупный, хорошо читаемый: тексты вопросов длинные и юридические.
- PWA-манифест и иконка (офлайн-режим на этапе 5).

### Главная `/`
- Заголовок: «Подготовка к аттестации по промбезопасности. Бесплатно, без регистрации».
- Сетка карточек областей: код, название, число вопросов, «База актуальна на …». Если по области есть прогресс, на карточке показана готовность.
- Поиск по вопросам вверху: «Найдите вопрос по тексту».
- Ниже блок «Как это работает» (3 пункта) и FAQ (для SEO).

### Страница области `/[area]`
- Название, плашка готовности, серия дней.
- Три большие кнопки: **Тренировка** (основная), **Экзамен**, **Ошибки (N)**.
- Статистика: изучено / освоено / всего.
- Ниже список всех вопросов ссылками на SEO-страницы (с пагинацией или раскрывающимся списком). Это важно для внутренней перелинковки.

### Тренировка `/[area]/train`
- Вопрос → выбор ответа → мгновенная подсветка (зелёный/красный) → правильный ответ → объяснение и ссылка на норму (если проверено) → «Дальше».
- Сверху прогресс-бар готовности и счётчик сессии.
- Ссылка «Сообщить об ошибке в вопросе» (mailto или простая форма в лог).

### SEO-страница вопроса `/[area]/q/[slug]`
- Полностью SSG/ISR, работает без JS.
- H1 = текст вопроса (обрезанный, если очень длинный), варианты ответов, правильный ответ выделен, объяснение и норма.
- Ниже: «Предыдущий / Следующий вопрос», CTA «Тренируйте все N вопросов области {код}», 5 похожих вопросов (по FTS).
- `<title>`: `{начало вопроса} — ответ | Промбез {код}`.
- meta description: правильный ответ (обрезанный).
- Разметка schema.org `QAPage`, canonical, breadcrumbs.

### Поиск `/search?q=`
- Postgres FTS (`websearch_to_tsquery('russian', q)`) с ранжированием, подсветка совпадений.
- Результаты: вопрос, область, правильный ответ кратко, ссылка.
- Debounce 300ms, работает и через SSR (по прямой ссылке).

### `/about`, `/privacy`
Политика конфиденциальности с упоминанием Метрики и РСЯ (cookies). Баннер согласия на cookies минимальный, внизу экрана, не перекрывает контент.

## 7. SEO

- `generateStaticParams` для всех областей и вопросов, ISR (`revalidate`) после импорта новой версии банка.
- `sitemap.ts`: все страницы (при необходимости разбить по областям), `robots.ts`.
- Чистые ЧПУ на латинице, без query-параметров в индексируемых страницах.
- Страницы тренировки, экзамена и ошибок закрыть `noindex`: контент там клиентский.
- Core Web Vitals: LCP < 2.5s на мобильном, никаких тяжёлых библиотек на SEO-страницах.
- Подготовить подтверждение для Яндекс Вебмастера (meta-тег через env).

## 8. Реклама (РСЯ)

- Компонент `<AdSlot id="..." />`, ID блоков берутся из env. Если env пустой, блок не рендерится (удобно для dev).
- Feature flag `NEXT_PUBLIC_ADS_ENABLED`.
- Где показывать:
  - SEO-страница вопроса: под ответом и объяснением, плюс внизу страницы.
  - Тренировка: на плашке итога каждых 10 вопросов (**не** между вопросом и ответом).
  - Главная и страница области: один блок ниже основного контента.
- Где **не** показывать: экзамен, всё, что выше первого вопроса.
- Место под блок резервировать заранее (фиксированная min-height), чтобы не было CLS.

## 9. Импорт вопросов

`scripts/import-questions.ts --area a1 --file data/raw/a1.json --version "2026-xx"`

Входной формат:
```json
{
  "area": { "code": "А.1", "title": "...", "bank_version": "...", "bank_updated_at": "YYYY-MM-DD" },
  "questions": [
    {
      "number": 1,
      "text": "...",
      "answers": [ { "text": "...", "is_correct": true }, { "text": "...", "is_correct": false } ],
      "norm_ref": null
    }
  ]
}
```

Требования:
- Валидация через zod: у каждого вопроса хотя бы один правильный ответ и не меньше двух вариантов. Ошибки выводятся с номером вопроса.
- Upsert по `(area_id, number)`. Если вопрос из старой версии отсутствует в новой, ставим `is_active = false`, не удаляем.
- Если текст вопроса изменился, slug не меняем (иначе потеряем SEO).
- Нормализация текста: лишние пробелы, неразрывные пробелы, кавычки.
- В конце отчёт: добавлено / обновлено / деактивировано.

## 10. Нефункциональное

- Docker multi-stage, healthcheck-эндпоинт `/api/health`.
- Миграции применяются при старте контейнера (или отдельной командой в Dokploy).
- `.env.example` со всеми переменными: `DATABASE_URL`, `NEXT_PUBLIC_SITE_URL=https://prombez-game.ru`, `NEXT_PUBLIC_YM_ID`, `NEXT_PUBLIC_ADS_ENABLED`, `NEXT_PUBLIC_RSYA_BLOCK_*`, `YANDEX_VERIFICATION`.
- Метрика: цели `answer_given`, `session_10_done`, `exam_started`, `exam_finished`, `exam_passed`, `search_used`.
- Тесты Vitest обязательны для `lib/progress` (Лейтнер, готовность, выбор следующего вопроса) и `lib/exam`.
- Playwright: зайти на главную → выбрать область → ответить на вопрос → увидеть подсветку и объяснение.

## 11. Этапы работы (для Claude Code)

**Этап 1. Каркас.** Next.js, Tailwind, Drizzle, схема БД, миграции, docker-compose для локального Postgres, `.env.example`, базовый layout с темами.

**Этап 2. Импорт.** Скрипт импорта, тестовый JSON на 30 вопросов для одной области (выдуманные вопросы-заглушки, помеченные как тестовые), заполнение БД.

**Этап 3. Тренировка и прогресс.** `lib/progress` с тестами, страница области, тренировка, готовность, серия дней, работа над ошибками.

**Этап 4. Экзамен.** Генерация билета, таймер, результат.

**Этап 5. SEO.** Страницы вопросов, поиск, sitemap, robots, schema.org, noindex там, где нужно.

**Этап 6. Прод.** Реклама (под флагом), Метрика, cookie-баннер, privacy, Dockerfile, деплой на Dokploy, Lighthouse на мобильном ≥ 90.

После MVP (в этом спринте не делать):
- Аккаунты (вход по email-коду или через Яндекс ID) и синхронизация прогресса с сервером.
- Генерация объяснений через LLM (`scripts/generate-explanations.ts`) и ручная проверка с флагом `explanation_verified`.
- PWA с офлайн-режимом.
- Pro-подписка (без рекламы, безлимит экзаменов, PDF-шпаргалка) через ЮKassa.
- B2B-кабинет: компания добавляет сотрудников, назначает области и видит их готовность.
- Новые экзамены на том же движке: электробезопасность, охрана труда, НАКС.

## 12. Критерии готовности MVP

- [ ] С главной до первого вопроса один клик, без регистрации.
- [ ] Тренировка, экзамен и ошибки работают; прогресс сохраняется после перезагрузки.
- [ ] Шкала готовности считается и отображается корректно (покрыто тестами).
- [ ] У каждого вопроса своя индексируемая страница, есть sitemap.
- [ ] Поиск находит вопрос по куску текста.
- [ ] Удобно пользоваться на телефоне шириной 360px.
- [ ] Реклама не показывается в экзамене и не вызывает сдвигов вёрстки.
- [ ] Проект поднимается одной командой через Docker и задеплоен на prombez-game.ru.
